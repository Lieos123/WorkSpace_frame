# 本项目的工作规则

工作区总规则见 `D:\WorkSpace\AGENTS.md`（工具库位置、命名、归档、边界）。

## 任务收尾的固定动作

每次任务做完，按顺序做完这四件事，不要等我提醒：

1. 往 `LOG.md` 追加一条当日条目（做了什么 / 为什么 / 结果 / 下一步），写在新日期的小节里，日期倒序。
2. 更新 `README.md` frontmatter 的 `status` 和 `next` 两个字段。
3. `git add -A && git commit`，提交信息一句话说清这次改了什么。
4. 如果这次推进改变了项目层面的状态，跑一次 `node D:\WorkSpace\ws.mjs tree` 刷新项目树。

## 夜间清单

排给夜跑（夜间无人值守）做的事写在 `NIGHT.md`，一行一条：`- [待跑] 标题 | 说明或验收标准 | 来源 日期`。

- 开发过程中想到「适合夜里做」的任务 → 写成 `[待审]`，并在收尾时告诉用户等点头；**用户认可后才改成 `[待跑]`**，不要自己改。
- 只有用户能把项目级任务提升到工作区级 `NIGHT.md`（跨项目、动工作区基础设施的才值得提升）。
- 格式细则见 `D:\WorkSpace\CONVENTIONS.md` 第 5 节；执行机制见 `D:\WorkSpace\_night\README.md`。

## 不要做的事

- 不要把 `runs/`、`outputs/`、`artifacts/`、客户数据这类产物提交进 git（见 `.gitignore`，按项目实际调整）。
- 不要把索引类目录（`.codegraph\`、`.ua\`、`aoci*.txt`）搬到工具库，它们跟着项目走。
- 不要为了让统计好看而只写日志不提交，两者都要。
