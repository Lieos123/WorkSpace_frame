# 人话摘要槽（给"前日简报"写 3–5 句）

这是**整条简报链路上唯一需要模型写的**一小段。其余（数据、统计、清单、链接、HTML）全部由脚本确定性生成。
设计目标：**哪怕接手的是内网的慢/弱模型（如 Qwen 级别），也只花几分钟**——读一个小 JSON，写一个小 md，写完就完事。

## 你要做的

1. 读输入（**只读这一个文件**，别去翻别的）：
   `D:\WorkSpace\_night\brief\data-<前日日期>.json`
   里面的 `facts` 是已经算好的事实：`day`（各项目提交与日志）、`night`（昨晚夜跑的完成/未完成数）、
   `morning`（早检有没有跑）、`pending`（等你点头的条目）、`doneItems`（昨晚完成的条目）、`stuck`（没做完/搁置）。

2. 写输出（UTF-8，纯文本 markdown，**只写这一处**）：
   `D:\WorkSpace\_night\brief\notes-<前日日期>.md`

3. 内容要求：
   - **3–5 句**，每句一行，以 `- ` 开头。
   - 只写 `data-*.json` 里有的东西。**不猜、不编、不评价**（没有的数据就不提）。
   - 有值得注意的事就点出来，比如：某项目一次提交都没有 / 夜跑没跑成 / 有未完成条目 / 工作树没干净。
   - 中文，别用行话缩写。

## 格式示例（照这个样子写，内容换成当天的）

```markdown
- 昨天主要在推进《产研周报》：补了导出校验，提交 3 次。
- 昨晚夜跑完成 1 条（技能来源登记），没有未完成。
- 早检正常，工作树是干净的。
- 有 2 条待审，今天早上窗口里勾一下就能排进今晚。
```

## 兜底

- 读不懂、写不出来、或者超过 5 分钟：**直接跳过**。
  简报照样生成，只是少了这一段——缺一段人话远好过编一段假话，也远好过卡住整条链路。
- 写完不用自己提交：`_night\` 由工作区**根仓库**跟踪，`notes-*.md` 会随后续的框架提交（夜间/早间收口）一起进版本控制；同目录的 `data-*.json`、日期 `.html` 是生成物，不进版本控制。
