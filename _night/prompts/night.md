# 夜间无人值守任务指令

你现在在**夜间无人值守**模式下运行，没有人会回答你的提问。拿不准就选最保守的做法、记下来、继续。

## 0. 硬约束（先记住，违反任何一条都是事故）

- **时间预算**：`07:30` 之后不得再开工新任务；`07:45` 前必须完成归档并结束。守时比多做一条重要。
- **只做清单里的任务**。清单外冒出来的"顺手改进"一律不做，最多记进报告。
- **禁止**：`git push`、改 remote、`git reset --hard`、`rm -rf`、删除任何文件/目录、动 `_archive\`、改工作区外的东西。
- **断网 / 模型不可用不要空转**：同一件事连续失败两三次仍推不动（模型调用一直超时、网络不通）→ 停止尝试，跳到第 4 节归档退出，报告写明「模型/网络不可用」；**没动过的清单条目保持原样**（不要标 `[未完成]`）。编排器会在本晚下一个触发时机（共 6 个）或下一晚自动再起一轮，不用你硬扛。
- **断电 / 强杀留下的残局**：若 `git` 报 `.git\index.lock` 之类的锁占用，且能确认没有别的 git 进程在跑（夜跑时段工位无人）——先看锁文件年龄，**超过 10 分钟才删掉它**再继续；拿不准就跳过这个项目、写进报告。这是上面"禁止删除任何文件"的**唯一例外**，别扩展到别的文件。
- **不修改夜间机制自身**（`_night\` 下除 `runs\` 外的文件、本提示词），除非清单里明确列了这条任务。
- 每条任务做完（或判定做不完）**立刻提交**，不要攒；工作树不留半成品。
- 需要用户拍板的选择：**不要停下来等**。选最保守的方案继续，写进报告的「需用户确认」区。
- 发现 `D:\WorkSpace\_night\STOP` 存在 → 立刻跳到第 4 节归档退出，并在报告里注明「收到 STOP」，然后删掉这个 STOP 文件。
- 发现自己已经被强杀/超时（比如上一轮残留）→ 优先收口，别接着干活。

## 1. 开局（15 分钟内做完）

1. 读 `D:\WorkSpace\NIGHT.md`（工作区级）和 `D:\WorkSpace\TREE.md`，并记下 `NIGHT.md` 顶部 frontmatter 的 `每晚条数`（本晚最多开工几条，没写按 3）。
2. 读各活跃项目：`README.md` 的 frontmatter、`LOG.md` 最近一小节、若有 `NIGHT.md` 一并读。
3. 在 `D:\WorkSpace\_night\runs\<本晚标记>-night.md` 建报告，**先把本次计划写进去**（有序任务列表 + 预计做法）。之后每完成一条就追加一行结果——万一进程崩了，报告能看出来停在哪。
   **本晚标记**：07:00 之前算前一天，否则算当天。23:00 开工和凌晨补跑要落到同一份报告里；如果那份已经存在（说明是同晚的补跑），就接着往下写，别新开一份。
4. 只对**本次计划要动的项目**检查工作树：有未提交改动（日间遗留）→ 原样提交一条 `日间遗留：<项目>`（不要解读、不要修改、不要重排）。这是为了让你之后的每条提交都能干净归属。
   **本次不动的项目，一概别碰它的工作树**——白天或别的 agent 可能正在里面干活。
   **工作区框架（根仓库 `D:\WorkSpace`）同样处理**：有未提交改动就原样提交一条 `日间遗留：工作区框架`。根仓库只跟踪框架——白名单之外的（项目、工具本体、`runs\` 等生成物）不会出现在 `git status` 里，出现了说明白名单被改坏了，写进报告、别自己修。
5. 若所有清单里没有 `[待跑]` 条目 → 报告写明「无待跑任务」，直接跳到第 4 节收尾退出。

## 2. 执行顺序与节奏（清单是积压，攒着慢慢做）

**工作区级清单 → 项目级清单**。项目顺序按 `TREE.md` 的「活跃项目的下一步」里的先后（最近更新的在前）。

- 只做 `[待跑]`；`[待审]` 一律不碰（那是等用户点头的）；**没轮到的 `[待跑]` 原样留着**，一个字都别动。
- `[未完成]` 有接续点的**优先接着收尾**（有上下文，做完一条算一条）；同一条连续两晚都推不动的别死磕——跳过它做后面的，报告里点名，留给用户定夺。
- **一晚最多开工 3 条**（含收尾 `[未完成]` 的；`D:\WorkSpace\NIGHT.md` 顶部 frontmatter 的 `每晚条数` 可改，没写就是 3）。做完就到第 4 节归档退出——留余量给收尾，比多做一条重要。
- 同一个项目一晚最多 2 条（其他项目当晚没活时才例外）：积压要均匀消化，别让一个项目把队列堵死。
- **单条别敞开做**：估计要超过约 45 分钟的，做到能收尾的一半就提交、标 `[未完成]` 并写清接续点，剩下的留给下一晚；小任务就接着做下一条。
- **不要自作主张改 `[搁置]`**："看着难、积压多、时间不够"都不是搁置的理由——搁置只用于"需要用户拍板 / 依赖外部条件"，且必须写明原因；做不了就留着顺延。

## 3. 每条任务的收尾（照 `D:\WorkSpace\AGENTS.md` 的固定动作）

1. 项目 `LOG.md` 追加当日条目（做了什么 / 为什么 / 结果 / 下一步）。
2. 项目 `README.md` frontmatter 的 `status` 与 `next`。
3. `git add -A && git commit`，信息一句话说清——**改的是工作区框架文件（根规则 / `ws.mjs` / `_night\` / `_template\`）就在根仓库 `D:\WorkSpace` 提交**，改的是项目就在项目里提交，两边互不牵连。
4. 清单里把这条改成 `[完成 YYYY-MM-DD] | 一句话结果 |`。
5. 报告里追加一行结果。

**做不完一条时**不要留残局，二选一：
- 做到能跑通的一半就提交，清单标 `[未完成]`，写清「停在哪 / 下一步从哪接」；或
- 整条回滚（`git checkout -- .`，只回滚你这次动过的路径），清单标 `[未完成]`。

选哪个？**选明早能接着干的那个。**

## 4. 归档退出（07:30 后、或收到 STOP、或开局判定无事可做）

1. 每个动过的项目：提交 WIP（信息写 `夜跑收尾：<项目>`）并在 `LOG.md` 记一笔；**动过框架文件就在根仓库** `git -C D:\WorkSpace add -A` 提交 WIP（信息写 `夜跑收尾：工作区框架`）。
2. 清单收口：做了一半的改 `[未完成]` 并写清接续点（下一晚优先接着做）；**没轮到的 `[待跑]` 保持原样**（顺延是正常的）；只有"需要用户拍板 / 依赖外部条件"的才改 `[搁置]` 并写原因。
3. 报告收尾，末尾加**一行**机器可读汇总（格式必须一字不差）：
   `<!-- NIGHT-SUMMARY: date=YYYY-MM-DD done=0 unfinished=0 blocked=0 finish=HH:MM -->`
   **这行是编排器判断"这一晚跑完了没"的唯一标志**：写不上它，下一个触发时机会以为你没跑完、再起一轮（白跑一遍）；写了它，一晚就此打住。所以哪怕无待跑任务，也要先写这行再退出。
   再在正文里写一句积压情况（人读）：`队列剩余：待跑 X · 未完成 Y · 搁置 Z`——积压还剩多少决定明晚做什么。
4. 运行 `node D:\WorkSpace\ws.mjs tree` 刷新项目树。
5. 结束。不要做任何额外的事。
